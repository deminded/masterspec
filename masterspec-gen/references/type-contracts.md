# Условия генерации по типу

Читай только раздел целевого типа. Это дополнение к его шаблону, а не причина загружать все
шаблоны/реестры. Общая форма — [spec-writing.md](../../masterspec/references/spec-writing.md).
Отсутствующий факт обрабатывается дозапросом или `OPEN`; не заполняй его по примеру.

## fn, as, rules, nfr, context

- `fn`: альтернативные/исключительные потоки и проверяемые AC given-when-then.
  Прочитай [operational-envelope.md](../../masterspec/references/operational-envelope.md):
  external-I/O требует восемь OE и четыре поля каждой грани; internal-only — точную N/A-строку.
  `APPLICABLE` имеет источник и AC, `N/A` — причину, `OPEN` блокирует готовность.
- `as`: назначение, границы, потребители, что умеет и не умеет.
- `rules`: абстрактная формулировка без компонентов/таблиц, атрибут `immutable`.
- `nfr`: числовая метрика результата с единицей, квалификаторами и основанием
  `-> fn-<slug>/OE-LOAD`; не выдумывай отсутствующие числа, проставь `immutable`.
- `context`: полный внешний путь OE-DELIVERY, предпосылки, подтверждения и silent failure.

## cdm, dict

- `cdm`: состояния и переходы — полная матрица состояние × событие, у перехода триггер и момент.
  Каждая связь имеет тип composition/aggregation/association/inheritance и бизнес-смысл.
- `dict`: значения и ссылка на сущность `cdm`, владеющую структурой справочника.

## cmp

Стабильные возможности `cap-*` внутри компонента: вход, выход и функции-потребители.
Не создавать отдельные файлы возможностей или порядок их вызова.

## scn

Порядок вызова возможностей, каждое ветвление с ≥2 явными исходами; один внешний вызов — один
шаг/узел со своим `api`. Укажи spec-владельца каждой реализуемой APPLICABLE OE и `tc-int`;
union сценариев покрывает все грани функции.

Выбери форму по [scenario-notation-registry.md](../../masterspec/references/scenario-notation-registry.md):
`yaml-graph` по умолчанию; `sequence`/`workflow`/`bpmn` требуют «Участники» с резолвингом в
`cmp/cap` и `api` для внешних вызовов. У `bpmn` поведение только в XML-сайдкаре, без пересказа
в компаньоне. Оставляй одну форму поведения; не генерируй все варианты шаблона одновременно.

## alg

Логика словами, полные ветвления (каждое «если» с «иначе»), инварианты.
`procedural` по умолчанию; `decision-table` — когда вход уже задан классификатором
«условия → результат». Обязательны Hit policy и покрытие комбинаций; поле ← источник живёт в `api`.

## api, data

Обязательны машинный сайдкар и компаньон по
[sidecar-formats.md](../../masterspec/references/patterns/sidecar-formats.md).

- `api`: вход, ответ-успех и ответ-отказ с типами; async — produce/consume. Структура только в
  сайдкаре; в .md — маппинги полей и недостающая семантика. Для внешнего OE-DELIVERY:
  стадии подтверждения, поздний/silent failure и reconciliation. Сохрани явный реестр
  `Business-reject codes` для каталога отказов.
- `data`: структура и выразимые ограничения только в сайдкаре; логические состояния, полный
  набор переходов и недостающие ограничения — у одного канонического владельца, по ссылке.
- `contract_origin: imported`: сайдкар заморожен; компаньон редактируется. Изменение структуры
  требует `evolve entry=ext` (запрос владельцу и реимпорт) либо решения человека
  `imported → authored` с `dr`. Не исправляй внешний контракт локально.

## lp, ui-view, nav

- `lp`: только из OE-LOAD; общая популяция отдельно от активного подмножества, бюджет работы
  на запуск и внешних операций. Неизвестные числа — OPEN требований.
- `ui-view`: состав, источники данных, состояния и исходящие переходы экрана.
- `nav`: граф переходов между `ui-view`; не повторяет содержимое экранов.

## tc-acc, tc-int, tc-flt

Для всех `fn` и `tc-*` обязательна `criticality: high|medium|low`.
Для `tc-acc`/`tc-int` прочитай
[test-case-standard.md](../../masterspec/references/test-case-standard.md): действие повелительным
глаголом, непустые testData и проверяемый expectedResult; для ошибок — отдельная проверка логов,
дополняющая пользовательское `OE-EVIDENCE`.

- `tc-acc`: конкретные AC и APPLICABLE OE, provenance fixture, fidelity и граница наблюдения.
- `tc-int`: ссылка на канонический OE-маппинг `scn`, fidelity и остаточный риск; без второй OE-таблицы.
- `tc-flt`: один каталог на `scn`, детерминированный набор точек `scn→api`, результаты без домысла,
  стабильные связи строк с `tc-int`, глубина по criticality.
